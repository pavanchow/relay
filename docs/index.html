The point

The core is one function: run(pipeline, executor, limits) -> Report. The scheduler never spawns a process or a thread. It drives an Executor trait in virtual time. Swap in a mock executor and every rule is testable with no real work; swap in the shell executor and the same scheduler runs real commands.

What it guarantees

Dependency order, real parallelism up to N, failure propagation that skips a failed job's transitive dependents, content-hash caching that skips unchanged work, and full determinism with config-order tie-breaks. It pairs with Metronome, a from-scratch scheduler.
